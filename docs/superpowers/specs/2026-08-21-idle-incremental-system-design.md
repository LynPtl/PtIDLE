# PtIDLE 挂机增量系统策划与数值设计

**项目**：PtIDLE
**文档类型**：游戏策划 + 数值策划 + 后端实现导向规格
**版本**：v0.1
**日期**：2026-08-21
**状态**：第一版设计稿

---

## 1. 设计目标

PtIDLE 的挂机增量系统不是战棋之外的附属小游戏，而是整个游戏的生产底座。它承担三件事：

1. 给休闲玩家提供持续成长、资源管理和阶段突破的体验。
2. 给战棋系统提供卡牌、职业认证、战术消耗品等公平竞技资产。
3. 通过生产装备、仓储上限、材料转化和制造配方形成长期循环。

第一版目标是做出一个**轻量但完整的挂机闭环**：

```text
采集资源 -> 加工材料 -> 制造资产 -> 生产装备反哺采集 -> 仓储上限制造瓶颈 -> 继续扩展生产能力
```

这版不追求复杂科技树，也不急着接 PVP。它要先回答一个问题：玩家离开游戏几个小时，回来以后是否有清晰的收益、瓶颈、下一步目标和成长反馈。

---

## 2. 设计原则

### 2.1 公平战棋与挂机成长分离

挂机系统可以有数值成长，但这些数值只影响生产效率、仓储能力、配方解锁和资产储备，不直接带入战棋基础属性。

允许成长的内容：

- 采集速度提高。
- 加工效率提高。
- 制造成本降低或批量能力提升。
- 仓储容量提高。
- 可制造的卡牌、认证装置、消耗品种类增加。

禁止带入公平战棋的内容：

- 棋子基础血量因为挂机等级变高而增加。
- 战棋卡牌因为稀有度更高而纯粹伤害更高。
- 职业认证装置出现数值品质差异，例如普通战士 20 HP、史诗战士 30 HP。

### 2.2 成长以瓶颈突破为核心

挂机系统的乐趣不应只是“每分钟数字变大”。第一版用三个瓶颈制造目标感：

- **速率瓶颈**：产出太慢，需要生产装备。
- **容量瓶颈**：仓库太小，必须扩容才能攒够高阶配方成本。
- **结构瓶颈**：单采一种资源无法推进，必须在采矿、伐木、草药之间切换。

### 2.3 第一版以规则可模拟为优先

所有数值都应该能被模拟器计算：

- 给定当前库存、装备和仓库上限，计算 N 分钟后的库存变化。
- 给定目标配方，计算当前缺口和推荐生产路径。
- 给定采集任务，计算预计收益、溢出和浪费。

如果一个规则不能被稳定模拟，先不进入第一版。

## 3. 第一版功能范围

### 3.1 包含

第一版包含以下系统：

| 系统 | 目标 |
|------|------|
| 资源采集 | 三个基础采集技能，产出一级资源和少量副产物 |
| 材料加工 | 将一级资源转化为标准材料 |
| 制造系统 | 制造生产装备、基础卡牌、职业认证、战术消耗品、仓库扩容件 |
| 生产装备 | 提供采集效率加成，按技能类型生效 |
| 仓储上限 | 按物品类型和关键资源限制容量，制造扩容件提升上限 |
| 离线结算 | 使用和在线采集一致的收益、加成、容量规则 |
| 规则模拟 | 预测收益、溢出、配方缺口、下一步建议 |

### 3.2 不包含

第一版暂不包含：

- 符文镶嵌。
- 装备强化到十几阶。
- 随机词条和洗练。
- 远征地城。
- PVP 战棋结算。
- 多角色并行任务队列。
- 市场交易。

这些内容可以在规则内核稳定后扩展。

## 4. 玩家体验目标

### 4.1 第一次进入

玩家初始拥有：

- 3 个白板棋子。
- 空库存。
- 默认仓储上限。
- 采矿、伐木、草药学三个基础采集入口。
- 冶炼、木工、研磨三个基础加工入口。

玩家的第一小时目标：

1. 采集铁矿石、煤炭、原木、草药。
2. 加工出铁锭、木板、草药粉末。
3. 制造第一件生产装备。
4. 感受到某个采集技能明显变快。

### 4.2 第一天目标

玩家应能完成：

- 制造矿镐、伐木斧、采集手套中的至少一件。
- 制造 1 个职业认证装置。
- 制造一批基础移动卡和轻击卡。
- 遇到第一次仓储瓶颈。
- 通过制造扩容件突破瓶颈。

### 4.3 第一周目标

第一版不做长线深层内容，但需要为后续保留位置。第一周目标可以是：

- 三个生产装备都拥有。
- 三个职业认证都各制造至少一个。
- 基础战棋资产库存成型。
- 仓储上限从初始值提升 2 到 3 次。
- 能通过模拟器看到“为了造某个目标还缺什么”。

## 5. 资源与物品体系

### 5.1 物品类型

后端统一库存采用 `inventory_items`，第一版沿用以下 `item_type`：

| item_type | 中文 | 是否堆叠 | 作用 |
|-----------|------|----------|------|
| resource | 一级资源 | 是 | 采集直接产出 |
| material | 加工材料 | 是 | 制造配方主要输入 |
| gear | 生产装备 | 可堆叠或实例化 | 提高采集效率 |
| certification | 职业认证 | 实例化 | 后续绑定棋子职业 |
| card | 卡牌 | 可堆叠或实例化 | 后续进入战棋牌库 |
| consumable | 战术消耗品 | 是 | 后续进入战棋或远征 |
| storage | 仓储扩容件 | 可消耗 | 提高容量上限 |

当前数据库还没有 `storage` 类型。第一版实现时有两个选择：

- 保守做法：扩容件作为 `gear` 或 `consumable` 的一种，使用后直接修改 `players.warehouse_limits`。
- 推荐做法：扩展 `inventory_items.item_type` 允许 `storage`，让扩容件在库存模型里有明确类型。

### 5.2 一级资源

| key | 中文名 | 来源 | 初始用途 |
|-----|--------|------|----------|
| iron_ore | 铁矿石 | 采矿主产物 | 冶炼铁锭 |
| coal | 煤炭 | 采矿副产物 | 冶炼燃料 |
| wood | 原木 | 伐木主产物 | 木工加工 |
| sap | 树液 | 伐木副产物 | 消耗品、扩容件 |
| herb | 草药 | 草药学主产物 | 研磨草药粉末 |
| mushroom | 荧光菇 | 草药学副产物 | 法师认证、药剂 |

### 5.3 加工材料

| key | 中文名 | 配方 | 用途 |
|-----|--------|------|------|
| iron_ingot | 铁锭 | 铁矿石 + 煤炭 | 装备、认证、卡牌 |
| plank | 木板 | 原木 | 装备、卡牌、扩容 |
| herb_powder | 草药粉末 | 草药 | 药剂、法师资产 |
| resin | 树脂 | 树液 | 扩容件、防护道具 |
| glow_extract | 荧光萃取液 | 荧光菇 + 草药粉末 | 法师认证、特殊消耗品 |

第一版可以只实现前三个，后两个作为预留配置。

## 6. 采集系统

### 6.1 基础采集技能

| 技能 | key | 主产物 | 主产物基础速率 | 副产物 | 副产物概率 | 副产物数量 |
|------|-----|--------|----------------|--------|------------|------------|
| 采矿 | mining | iron_ore | 1.0 / 分钟 | coal | 30% | 主产物数量的 50%，向下取整，至少 1 |
| 伐木 | woodcutting | wood | 1.0 / 分钟 | sap | 20% | 主产物数量的 50%，向下取整，至少 1 |
| 草药学 | herbalism | herb | 1.0 / 分钟 | mushroom | 30% | 主产物数量的 50%，向下取整，至少 1 |

### 6.2 采集时长

第一版保留短任务，便于测试和前端反馈：

| 场景 | 时长 |
|------|------|
| 开发/测试默认 | 60 秒 |
| 正式体验默认 | 10 分钟 |
| 离线模拟最小粒度 | 1 分钟 |
| 单次离线结算上限 | 24 小时 |

后端可以通过环境变量或规则配置切换默认任务时长。

### 6.3 采集收益公式

```text
基础数量 = 基础速率 * 任务分钟数
装备倍率 = 1 + sum(匹配技能的生产装备加成)
技能倍率 = 1 + 技能等级加成
场景倍率 = 1 + 场景加成 - 场景惩罚
理论收益 = floor(基础数量 * 装备倍率 * 技能倍率 * 场景倍率)
实际入库 = min(理论收益, 剩余容量)
溢出 = 理论收益 - 实际入库
```

第一版可以先把 `技能倍率` 和 `场景倍率` 固定为 1，只实现装备倍率和容量限制。

### 6.4 副产物规则

副产物不应每分钟独立随机一次，否则离线结算会不稳定。第一版建议使用确定性期望值：

```text
副产物理论收益 = floor(主产物理论收益 * 副产物概率 * 副产物系数)
```

例如采矿 60 分钟，铁矿石理论收益 60，煤炭概率 30%，副产物系数 0.5：

```text
coal = floor(60 * 0.3 * 0.5) = 9
```

这样测试、模拟器和离线收益都能稳定复现。

## 7. 加工系统

### 7.1 初始加工配方

| 类型 | 中文名 | 输入 | 输出 | 用途 |
|------|--------|------|------|------|
| smelting | 冶炼 | iron_ore x2 + coal x1 | iron_ingot x1 | 核心金属材料 |
| carpentry | 木工 | wood x2 | plank x1 | 木质结构与卡牌底材 |
| grinding | 研磨 | herb x2 | herb_powder x1 | 药剂和法术材料 |

### 7.2 加工批量

加工支持 `quantity` 批量参数。

```text
总输入 = 单次输入 * quantity
总输出 = floor(单次输出 * quantity * 加工效率)
```

第一版加工效率默认为 1.0。后续可通过生产设施、技能等级或工具提高。

### 7.3 加工失败策略

第一版不做加工失败概率。材料不足时整批失败，不发生部分扣除。

### 8.1 制造分类

| category | 中文 | 输出类型 | 第一版作用 |
|----------|------|----------|------------|
| gear | 生产装备 | gear + gear_instances | 提高采集效率 |
| card | 基础卡牌 | card + card_instances | 为战棋准备牌库资产 |
| certification | 职业认证 | certification + profession_certifications | 后续绑定棋子职业 |
| consumable | 战术消耗品 | consumable | 后续战棋或远征消耗 |

#### 生产装备

| 伐木斧 | iron_ingot x3 + plank x3 | woodcutting_axe x1 | 伐木收益 +50% |
| 采集手套 | plank x5 + herb_powder x1 | gathering_gloves x1 | 草药学收益 +30% |

#### 战棋资产

| 名称 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 战士认证装置 | iron_ingot x2 | warrior_certification x1 | 后续绑定战士职业 |
| 弓手认证装置 | plank x2 | ranger_certification x1 | 后续绑定弓手职业 |
| 法师认证装置 | herb_powder x2 | mage_certification x1 | 后续绑定法师职业 |
| 基础移动卡 | plank x1 | move x1 | 通用战术卡 |
| 基础轻击卡 | iron_ingot x2 | light_attack x1 | 通用攻击卡 |
| 治疗药剂 | herb_powder x2 | healing_potion x1 | 战术消耗品 |

当前迁移脚本中的基础移动卡输入是 `iron_ingot x1`。为了更符合“卡牌底材来自木板”的产线，建议改为 `plank x1`。如果要减少迁移改动，也可以暂时保留现状。

#### 仓储扩容

| 名称 | 输入 | 效果 |
|------|------|------|
| 简易资源仓 | plank x10 + iron_ingot x3 | resource 上限 +500 |
| 材料货架 | plank x8 + herb_powder x2 | material 上限 +250 |
| 卡牌收纳盒 | plank x6 + sap x2 | card 上限 +50 |

第一版可以先实现资源仓和材料货架，卡牌收纳盒等卡牌系统落地后再启用。

### 8.3 制造原子性

制造必须在一个数据库事务里完成：

1. 锁定玩家库存。
2. 校验配方存在。
3. 校验输入材料足够。
4. 校验输出容量足够。
5. 扣除输入。
6. 写入输出库存。
7. 如果输出是实例类物品，同时写入实例表。
8. 返回制造结果和制造后的关键库存。

任何一步失败都不能扣除材料。

## 9. 生产装备系统

### 9.1 装备生效规则

第一版采用自动生效，不做穿戴界面：

```text
某技能装备加成 = 该玩家拥有的、skill_type 匹配的 gear_instances 中最高 bonus_rate
```

理由：

- 当前还没有前端和装备槽位系统。
- 自动取最高值能减少 UI 需求。
- 后续加入穿戴/配装时，可以从“自动最高”迁移到“指定 loadout”。

### 9.2 多件装备叠加

第一版不做同类装备无限叠加。规则：

- 同一 `skill_type` 只取最高 `bonus_rate`。
- 不同 `skill_type` 互不影响。
- 同一装备重复制造可以保留库存数量，但不增加加成。

### 9.3 装备数值曲线

第一版只做 T1 装备：

| 阶段 | 加成范围 | 目标体验 |
|------|----------|----------|
| 无装备 | 0% | 感到初始慢，但可推进 |
| T1 装备 | 30% 到 50% | 明显变快，有第一波成长感 |
| T2 装备 | 80% 到 120% | 后续版本预留 |
| T3 装备 | 200% 以上 | 远期深度增量 |

## 10. 仓储系统

### 10.1 容量模型

仓储上限保存在 `players.warehouse_limits`。

第一版按 `item_type` 计容量：

| 类型 | 初始上限 | 说明 |
|------|----------|------|
| resource | 1000 | 所有一级资源共享 |
| material | 500 | 所有加工材料共享 |
| gear | 50 | 生产装备共享 |
| certification | 10 | 职业认证共享 |
| card | 200 | 卡牌共享 |
| consumable | 100 | 消耗品共享 |

共享容量比每个物品独立容量更容易制造瓶颈。玩家如果一直挖矿，资源仓会被铁矿石挤满，从而逼迫加工或扩容。

### 10.2 容量计算

```text
已用容量(item_type) = sum(inventory_items.quantity where item_type = X)
剩余容量 = warehouse_limits[X] - 已用容量
可入库数量 = min(待入库数量, max(0, 剩余容量))
```

### 10.3 入库策略

采集结算采用部分入库：

- 容量够：全部入库。
- 容量不够：能放多少放多少，剩余记为 `overflowed`。

制造采用严格入库：

- 输出容量够：制造成功。
- 输出容量不够：制造失败，不扣材料。

理由：采集的溢出是挂机游戏常见反馈；制造失败则更符合玩家预期，避免材料被扣但成品放不下。

## 11. 离线结算

### 11.1 结算原则

离线收益不应有独立公式。它必须复用采集任务收益公式、装备加成和容量规则。

### 11.2 结算上限

| 参数 | 数值 |
|------|------|
| 最大离线时长 | 24 小时 |
| 最小结算粒度 | 1 分钟 |
| 默认任务时长 | 10 分钟 |
| 开发测试任务时长 | 60 秒 |

### 11.3 多任务限制

第一版仍然限制每个玩家同一时间只有一个活跃采集任务。这样更容易保证：

- 状态简单。
- 前端显示简单。
- 测试简单。
- 后续再扩展多角色并行队列。

## 12. 规则模拟器

### 12.1 模拟器目标

模拟器不是前端展示糖衣，而是后端规则自检工具。它应支持：

- 模拟某个采集任务完成后的收益。
- 模拟离线 N 分钟后的库存变化。
- 计算某个制造目标还缺哪些资源。
- 估算从当前库存到目标配方的最短生产路径。
- 标出会溢出的资源和浪费数量。

### 12.2 输入

```json
{
  "playerId": "uuid",
  "goal": {
    "type": "craft",
    "recipeName": "矿镐",
    "quantity": 1
  },
  "horizonMinutes": 60
}
```

### 12.3 输出

```json
{
  "goal": {
    "recipeName": "矿镐",
    "quantity": 1,
    "craftableNow": false
  },
  "missing": {
    "iron_ingot": 4,
    "plank": 2
  },
  "rawMaterialGap": {
    "iron_ore": 8,
    "coal": 4,
    "wood": 4
  },
  "recommendedActions": [
    {
      "action": "gather",
      "skillType": "mining",
      "minutes": 12,
      "reason": "需要铁矿石和煤炭来冶炼铁锭"
    },
    {
      "action": "gather",
      "skillType": "woodcutting",
      "minutes": 4,
      "reason": "需要原木加工木板"
    }
  ],
  "capacityWarnings": []
}
```

### 12.4 第一版推荐算法

第一版不做复杂最优化，采用规则启发：

1. 如果目标可直接制造，推荐制造。
2. 如果缺加工材料，反推加工配方所需一级资源。
3. 如果缺一级资源，按采集速率估算所需分钟数。
4. 如果预计采集会溢出，先推荐加工或扩容。
5. 如果多个缺口并存，按“当前最稀缺比例”排序。

## 13. API 设计草案

### 13.1 规则查询

```http
GET /api/idle/rules
```

返回采集、加工、制造、仓储、装备规则。前端用它渲染工坊界面。

### 13.2 收益预览

```http
POST /api/idle/simulate
```

输入目标和时间范围，返回收益预测、缺口和推荐行动。

### 13.3 制造配方查询


返回所有制造配方，支持按 `category` 过滤。

## 16. 测试与验收

### 16.1 单元测试

必须覆盖：

- 容量计算：空库存、满库存、部分可入库。
- 采集收益：无装备、有装备、副产物、溢出。
- 加工：材料足够、材料不足、批量加工、事务失败。
- 制造：每个 category 的输出行为。
- 装备加成：同技能取最高，不同技能隔离。
- 模拟器：目标可制造、缺材料、缺资源、容量不足。

### 16.2 集成测试

必须覆盖完整闭环：

1. 注册用户。
2. 开始采矿。
3. 完成采集并入库。
4. 加工铁锭。
5. 伐木并加工木板。
6. 制造矿镐。
7. 再次采矿，验证收益增加。
8. 制造职业认证或卡牌。
9. 查询仓库，验证容量摘要正确。

### 16.3 数值验收

第一版通过的标准：

- 30 到 60 分钟内能制造第一件生产装备。
- 2 到 4 小时内能形成三采集线循环。
- 1 天内能看到仓储瓶颈并完成第一次扩容。
- 没有任何挂机数值直接提高战棋基础属性。
- 所有收益模拟和实际结算一致。

## 17. 实施顺序建议

1. 统一库存和容量服务。
2. 修正加工系统，让它完全使用 `inventory_items`。
3. 实现制造规则服务。
4. 实现生产装备加成服务。
5. 改造采集结算，接入装备加成和统一容量。
6. 实现规则模拟器。
7. 增强仓库和规则查询 API。
8. 写完整闭环集成测试。

这个顺序先修正底座，再扩展玩法。否则制造和模拟器会建立在旧库存假设上。

## 18. 后续扩展路线

### 18.1 第二版：技能等级

- 每次采集、加工、制造获得对应技能经验。
- 每级提供小幅效率提升。
- 特定等级解锁高级配方。

### 18.2 第三版：生产设施

- 熔炉、木工台、研磨台、制卡机。
- 设施决定批量加工和制造上限。
- 设施升级形成新的材料消耗池。

### 18.3 第四版：远征地城

- 独立于公平战棋的数值膨胀系统。
- 通过自动战斗校验产出特殊材料。
- 特殊材料进入机制卡牌、符文和高级消耗品。

### 18.4 第五版：符文与机制组件

- 符文改变卡牌机制，而不是纯数值强化。
- 强机制通过能量消耗、前置站位、冷却或消耗品成本平衡。

## 19. 当前决策摘要

| 决策 | 结果 |
|------|------|
| 第一版方向 | 规则和数值优先 |
| 成长重点 | 生产装备、仓储扩容、战棋资产三条线轻量并行 |
| 核心交付 | 可模拟、可测试、可解释的挂机闭环 |
| 战棋接入 | 只准备资产，不实现对战 |
| 数值风格 | 初期克制，后续允许生产侧膨胀 |
| 随机性 | 第一版采集副产物用确定性期望值 |
| 装备生效 | 第一版自动取同技能最高加成 |
